Run the smallest normative gate

A conformance corpus is executable contract data: each case names a language rule, input, expected canonical form, English reading, result, completeness, and evidence shape. Unlike an ordinary unit test written around implementation details, another implementation can consume the same JSON corpus.

Terminal · core-0.1 conformance

What this proves—and what it does not

It proves the current executable agrees with all 26 normative examples. It catches changed notation, ordering, readings, results, completeness labels, and proof shapes represented there. It does not prove every possible program correct. Later chapters add independent models, generated inputs, regression comparison, and hostile-input tests because each kind of evidence catches a different failure.

03

Learn enough TFL to predict the machine

The point is not memorizing symbols. It is learning what each sign commits the program to, so the later answers can surprise you only for logical reasons.

One proposition, two signed terms

At the basic level, the first sign controls the subject quantity and the second controls predicate quality. The letters A, E, I, and O are traditional names for the four categorical forms; Dualithor’s semantics are fixed by core-0.1, not by the labels.

FormTFLReadingCommitment
A−S+PEvery S is PUniversal inclusion; does not assert an S exists.
E−S−PNo S is PUniversal exclusion; does not assert an S exists.
I+S+PSome S is PAsserts a witness that is both S and P.
O+S−PSome S is not PAsserts a witness that is S and not P.

Fixed references

A trailing * makes a name singular: Socrates* denotes one fixed individual. Its subject sign can be ±, read as a wild quantity, because universal and particular orientation coincide for that fixed reference.

±Socrates*+Man reads “Socrates is a man.”

Open-world commitment

The program does not treat missing information as false. “Every unicorn is white” remains true if there are no unicorns, and it does not imply “some unicorn is white.” Explicit negative support is different from absent positive support.

Let the renderer audit your reading

render parses one proposition, prints a deterministic English display, and prints canonical source spelling. It performs no inference and loads no file. ASCII - and +- are accepted; the printer emits typographic − and ±.

Terminal · four categorical forms
opam exec -- dune exec tfl -- render '-Man+Mortal'
opam exec -- dune exec tfl -- render '-Man-Dog'
opam exec -- dune exec tfl -- render '+Dog+Friendly'
opam exec -- dune exec tfl -- render '+Dog-Friendly'
Expected readings, in order
every man is mortal
no man is dog
some dog is friendly
some dog is not friendly
Names, Unicode, compounds, relations, and proposition terms
  • Bare names start with an ASCII letter. Quote ordinary Unicode or punctuation-bearing names: "Élan".
  • (−Dog) is the negative term “non-dog.”
  • (+White+Horse) is one compound term, “white horse,” not two individuals.
  • (Loves+Logician) is a relational term, “loves some logician.”
  • [+p+q] turns a proposition into a term. Its special Boolean semantics apply only in eligible equivalence checks.

English is an audit display, never the semantic authority. The formal TFL tree and the decision procedure determine results.

Prediction: Does −Unicorn+White establish +Unicorn+White?
No. The universal has no existential import. It classifies any unicorn that exists, but does not create a unicorn witness. The complete atomic procedure can produce an invalid result for that attempted inference.
04

Compile your first real .tfl file

A program is UTF-8 text with one proposition per nonblank physical line. Two minus signs begin a comment outside a quoted name.

The next command creates the dedicated tour directory when needed and overwrites exactly one example file inside it. It does not touch the repository. The directory survives a reboot or a multi-day pause until you choose the cleanup command at the end.

Terminal · create the foundations program
mkdir -p /home/serrecchia/dualithor-phase5-tour
printf '%s\n' \
  '-- Named individuals' \
  '±Socrates*+Man' \
  '±Fido*+Dog' \
  '' \
  '-- Classifications and exclusions' \
  '−Man+Human' \
  '−Human+Mortal' \
  '−Dog+Animal' \
  '−Animal+Mortal' \
  '−Man−Dog' \
  > /home/serrecchia/dualithor-phase5-tour/foundations.tfl
Terminal · compile the complete file
opam exec -- dune exec tfl -- check /home/serrecchia/dualithor-phase5-tour/foundations.tfl
Expected
/home/serrecchia/dualithor-phase5-tour/foundations.tfl: OK (7 statements)
What check actually checks

The loader verifies the case-sensitive .tfl suffix, regular-file type, one-mebibyte byte limit, and well-formed UTF-8. The runtime then parses and validates every nonblank, non-comment line. Compilation is all-or-nothing: one malformed line prevents an executable program rather than silently dropping that line.

check does not claim the propositions are mutually consistent. A syntactically valid contradiction compiles. Consistency is a separate logical operation because “well-formed text” and “satisfiable knowledge” are different ideas.

05

Ask three questions: yes, no, and unknown

This is the conceptual center of the tour. Dualithor answers whether a proposition follows from the program, not whether it happens to be true in the real world.

Before the commands: entailment and completeness

A program entails a query when every interpretation satisfying the program also satisfies the query. A complete decision procedure for a fragment can always settle every accepted case in that fragment. An incomplete search may still find sound proofs, but a miss means only “this bounded procedure did not find support.”

Complete does not mean “more confident.” A proof from an incomplete method is still sound. Completeness governs what a failed search is allowed to conclude. It is a property of the method over a defined fragment, not a percentage attached to one answer.
Query 1 — positive support

Predict first: Socrates is a man; every man is human; every human is mortal.

Terminal · expect yes and status 0
opam exec -- dune exec tfl -- query /home/serrecchia/dualithor-phase5-tour/foundations.tfl '±Socrates*+Mortal'
printf 'exit status: %s\n' "$?"
Key lines
yes — the query follows
Method: PZ (complete)
exit status: 0
Query 2 — the contradictory follows

Ask whether Socrates is not human. The program supports the exact opposite.

Terminal · expect no and status 1
opam exec -- dune exec tfl -- query /home/serrecchia/dualithor-phase5-tour/foundations.tfl '±Socrates*−Human'
printf 'exit status: %s\n' "$?"
Key lines
no — the contradictory follows
Method: PZ (complete)
Support: Socrates is a human [+Human+Socrates*]
exit status: 1
Query 3 — complete open-world unknown

Fido is a dog, animal, and mortal. Nothing connects Fido to Human or non-Human.

Terminal · expect unknown and status 1
opam exec -- dune exec tfl -- query /home/serrecchia/dualithor-phase5-tour/foundations.tfl '±Fido*+Human'
printf 'exit status: %s\n' "$?"
Key lines
unknown — neither the query nor its contradictory follows
Method: PZ (complete)
exit status: 1

Because the P/Z method is complete for this atomic categorical fragment, this unknown is not a search timeout. It exactly establishes that neither “Fido is human” nor “Fido is not human” follows from the program.

What the P/Z method is doing

For atomic categorical propositions, universals become implication links and their contrapositives. Particulars and fixed references create witness points. The method asks whether adding the query’s contradictory makes a witness impossible. That closure method is complete under core-0.1’s no-existential-import semantics.

yes
The query has sound support. Exit status 0.
no
The contradictory has support. With a complete method, this is logical non-entailment. Exit status 1.
unknown
Neither side is established. Read the completeness line to distinguish exact open-world non-entailment from an incomplete search.
Prediction: Is “unknown (complete)” weaker or stronger than “unknown (incomplete)”?
It is a stronger negative result. Complete unknown establishes that neither side follows. Incomplete unknown says only that the bounded procedure found neither side.
06

Ask “what follows about Socrates?”

A description query turns one fixed yes/no question into a bounded collection of supported classifications.

The current procedure saturates selected inference rules, keeps answers about the requested term, removes answers implied by stronger retained answers, and sorts the result deterministically. It deliberately does not promise the set is exhaustive.

Terminal · supported descriptions
opam exec -- dune exec tfl -- describe /home/serrecchia/dualithor-phase5-tour/foundations.tfl 'Socrates*'
printf 'exit status: %s\n' "$?"
Observed answer set
Socrates is non-dog
Socrates is non-Fido
Socrates is a human
Socrates is a man
Socrates is a mortal
Method: bounded-saturation (incomplete: bounded-term-saturation)
exit status: 3
Status 3 is useful output, not a crash. Every displayed answer has a derivation. Status 3 says the bounded procedure cannot promise there are no additional answers. Treating this as status 0 would overclaim exhaustiveness; treating it as “nothing worked” would discard proven information.
Inspect why “Socrates is non-Fido” appears

The human display is intentionally compact. Machine mode retains the full proof. This filter selects the surprising answer and its support.

Terminal · proof behind one answer
opam exec -- dune exec tfl -- describe --json /home/serrecchia/dualithor-phase5-tour/foundations.tfl 'Socrates*' |
  jq '.answers[] | select(.proposition.tfl == "±Socrates*+(−Fido*)") | {proposition, support}'

The explanation ties together “Socrates is a man,” “Fido is a dog,” and “no dog is a man.” The proof lines record the immediate rules and substitutions rather than asking you to trust the English summary.

07

Keep the program alive in the REPL

REPL means read–evaluate–print loop: read one command, evaluate it against one compiled program, print a result, then wait for the next command.

Start this interactively in your own terminal. The file compiles once. Command history is held only in this process’s memory; it is not written to a history file.

Terminal · interactive command
opam exec -- dune exec tfl -- repl /home/serrecchia/dualithor-phase5-tour/foundations.tfl

At the tfl> prompt, open these turns one at a time and type only that line.

REPL turn 1 — query a chain
Type at tfl>
query ±Socrates*+Mortal

Expect yes, method PZ, complete.

REPL turn 2 — ask for descriptions
Type at tfl>
describe Socrates*

Expect the same five supported answers and the incomplete bounded-saturation label.

REPL turn 3 — check the whole program
Type at tfl>
consistency

Expect consistent under the complete P/Z procedure.

REPL turn 4 — compare a contrapositive
Type at tfl>
equivalence −Man+Human <=> −(−Human)+(−Man)

Expect equivalent with a rewrite witness. The method is incomplete: finding a path proves equivalence; failure to find one would not prove non-equivalence.

REPL turn 4b — trigger complete propositional truth-table equivalence

For eligible lowercase, relation-free forms, square brackets give a one-member propositional interpretation. The runtime can compare the two sides by a complete truth table rather than bounded rewrite search.

Type at tfl>
equivalence −[p]+[q] <=> −p+q

Expect equivalent with method dnf (complete).

REPL turn 5 — make a recoverable syntax error
Type at tfl>
query +

Expect a syntactic diagnostic and another prompt. The compiled program remains loaded.

REPL turn 6 — prove the error did not poison the session
Type at tfl>
query ±Fido*+Mortal

Expect yes. This is the recovery property, not merely another query.

REPL turn 7 — reload safely, then leave
Type one line at a time
reload
quit

A successful reload recompiles the original path and atomically replaces the in-memory program. A failed reload would retain the last valid program.

Optional: reproduce the session as a deterministic pipe transcript

Piped sessions suppress the prompt. This is how process tests can compare the whole conversation without pretending to type at a terminal.

Terminal · non-interactive transcript
printf '%s\n' \
  'query ±Socrates*+Mortal' \
  'describe Socrates*' \
  'consistency' \
  'equivalence −Man+Human <=> −(−Human)+(−Man)' \
  'query +' \
  'query ±Fido*+Mortal' \
  'reload' \
  'quit' |
  opam exec -- dune exec tfl -- repl /home/serrecchia/dualithor-phase5-tour/foundations.tfl

Query support and program consistency are separate. The current query checker can stop after the first supported side; a separate consistency operation asks whether the entire premise set clashes.

Terminal · create an inconsistent program

  '±Socrates*+Man' \
  '−Man+Mortal' \
  '±Socrates*−Mortal' \

First prove the distinction: this file still compiles because all three statements are valid source.

Terminal · syntax and fragment check
opam exec -- dune exec tfl -- check /home/serrecchia/dualithor-phase5-tour/inconsistent.tfl

Now request the consistency record and retain its proof lines through JSON mode.

Terminal · inconsistency evidence
printf '%s\n' 'consistency' 'quit' |
  opam exec -- dune exec tfl -- repl --json /home/serrecchia/dualithor-phase5-tour/inconsistent.tfl |
  jq -c 'select(.operation == "consistency") | {status, method, completeness, evidence}'
What to locate in the JSON
"status":"inconsistent"
"method":"PZ"
"complete":true
"rule":"DON"
"rule":"contradiction"
"tfl":"⊥"

The proof combines “Socrates is a man” and “every man is mortal” to derive “Socrates is mortal,” then clashes it with the explicit “Socrates is not mortal.” The final ⊥ symbol marks impossibility.

Do not call the current query system four-valued or paraconsistent. The public both result is not implemented in core-0.1. A query returns the first supported side it finds. Use consistency separately to expose contradictory knowledge until the later roadmap fixes the final contract.
09

Move beyond atomic categories

Compound and relational terms are where bounded derivation replaces the complete atomic P/Z procedure. This is the right place to feel the difference between a sound proof and an exhaustive search.

Compound term

(+White+Horse) is one term—“white horse.” A universal classification of that whole term can be substituted into a positive occurrence.

Relational term

(Loves+Logician) is “loves some logician.” The plus sign on the object supplies existential quantity. The relation head and its object roles remain formal.

The rule you will see is DON, dictum de omni: a universal classification may replace a positive occurrence of its subject with its predicate. Learn that idea before reading the proof below.

Terminal · create compound and relational facts
mkdir -p /home/serrecchia/dualithor-phase5-tour
printf '%s\n' \
  '-- A compound term is one combined classification' \
  '+Knight+(+White+Horse)' \
  '−(+White+Horse)+Gentle' \
  '' \
  '-- A relation can contain a quantified object' \
  '±Ada*+(Loves+Logician)' \
  '−Logician+Human' \
  > /home/serrecchia/dualithor-phase5-tour/relations.tfl
Terminal · two sound derivations
opam exec -- dune exec tfl -- query /home/serrecchia/dualithor-phase5-tour/relations.tfl '+Knight+Gentle'
opam exec -- dune exec tfl -- query /home/serrecchia/dualithor-phase5-tour/relations.tfl '±Ada*+(Loves+Human)'

Optional: watch an indirect proof refute a counterclaim

An indirect proof temporarily adds the contradictory of the requested conclusion as a counterclaim. If the premises plus that counterclaim derive ⊥, the original query has support. This is classical proof by contradiction, with every introduced line visible.

Touch the inherited numerical fragment—without overselling it

Levels 1–3 exist today, but they are a limited sufficient-condition checker. Full Numerical Term Logic is future work, not a completed Phase 5 feature.

SourcePrintedDisplay quantity
+C^1+P+C¹+Pmany C are P
+C^2+P+C²+Pmost C are P
+C^3−H+C³−Hfew C are H, represented through the predominant complement

The numerical method checks three conditions: algebraic term balance, matching counts of particular premises and conclusions, and a permitted carried quantity level. Passing all three proves validity. Failing one proves only unknown; it never proves invalidity.

11

Break a file on purpose and audit the diagnostics

Phase 5’s value is easiest to judge when input is wrong: independent errors should survive together, point at the original Unicode text, and say what kind of failure occurred.

Know the failure vocabulary first

ClassMeaning today
lexicalThe tokenizer cannot form a valid token, such as an unquoted non-ASCII bare name.
syntacticValid tokens do not form a complete proposition, or nesting exceeds the cap.
name_resolutionReserved for future declarations; no current core-0.1 source can produce it.
outside_fragmentThe text parses, but the requested inference procedure does not support that shape.
incomplete_searchAn accepted operation stopped without an exhaustive logical result.
resource_limitValid-shaped input exceeded a documented size or work budget.
internalAn unexpected implementation defect reached the total boundary; it is not blamed on user text.
Terminal · create two independent errors
mkdir -p /home/serrecchia/dualithor-phase5-tour
printf '%s\n' \
  '  +"Élan"+Mammal' \
  '  +Élan+Mammal' \
  '  −Man+' \
  > /home/serrecchia/dualithor-phase5-tour/broken.tfl
Terminal · human diagnostics
opam exec -- dune exec tfl -- check /home/serrecchia/dualithor-phase5-tour/broken.tfl
printf 'exit status: %s\n' "$?"
Expected diagnostic shape
broken.tfl:2:4: lexical: Unexpected character 'É' (quote the term to use non-ASCII names)
  |   +Élan+Mammal
  |    ^
broken.tfl:3:8: syntactic: Expected a term, found end of input
  |   −Man+
  |        ^
exit status: 2

Line 1 proves quoted Unicode is valid. On line 2, the two leading spaces count, the plus sign is column 3, and É is column 4. Columns count Unicode code points, not UTF-8 bytes. A half-open span includes its start and stops immediately before its end, which makes adjacent spans unambiguous.

Inspect the same two source spans as JSON

Run the evidence ladder, understanding each rung

“The tests pass” is too vague. These gates compare Dualithor against different authorities, so their failures would mean different things.

First: do not confuse three kinds of completeness

Logic

Procedure completeness

A method can decide every accepted case in a defined logical fragment. P/Z has this contract for atomic categorical core-0.1.

Search

Bounded exploration

Derivation can find sound proofs but stop without exhausting every consequence. Its miss is unknown, not invalid.

Tests

Suite coverage

Passing examples never proves a suite has tested every behavior. Dualithor combines contracts, independent models, generators, regression comparison, and mutation audits.

Leave with the honest boundary in your head

The current kernel is real and usable. It is not yet the full language promised by the roadmap, and nonexistent features should not be redescribed as broken versions of something that exists.

Exists and was exercised

  • Parser, canonical printer, and deterministic English display
  • Categorical, fixed-reference, compound, relational, proposition-term, and limited levelled forms
  • Complete atomic P/Z decision and bounded non-atomic proof search
  • Whole-program compile, query, describe, consistency, and equivalence operations
  • UTF-8 .tfl files, human CLI, REPL, and two stable JSON schemas
  • Proofs or certificates, explicit completeness, source spans, and classified failures

Does not yet exist in core-0.1

  • Answer variables
  • User-defined rules and recursion
  • Modules, imports, declarations, or name resolution
  • Full Numerical Term Logic
  • Modal, relevance, free-term, or synthetic profiles
  • Negation as failure or implicit closed-world mode
  • A public both query result
The installed commands are real; the end-user distribution does not exist yet. This tour installs the current source package into an opam switch. Version 1 must ship precompiled tfl and dualithor artifacts that a normal user can install without first installing OCaml, opam, or Dune. Phase 38 owns that release work.

Current behavior that must retain its label

  • Relational and compound search is bounded and incomplete; a miss is not invalidity.
  • Term descriptions return proven answers but not a guaranteed exhaustive answer set.
  • The numerical layer is a sound sufficient-condition rule set, not a complete numerical decision procedure.
  • English can be awkward and is never authoritative over formal meaning.
  • Consistency for non-atomic programs can be undetermined when no contradiction is found.
  • Size and work budgets can return resource_limit instead of a logical result.
What Phase 6 actually is Phase 6 locks the primary sources, semantics, profile boundaries, proof procedures, completeness claims, and permitted combinations for the published extension family. It is contract and source work before extension syntax. The plan explicitly forbids implementing new extension syntax before that foundation agrees.
